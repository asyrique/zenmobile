# Zen Mobile

A mobile companion for [Zen Browser](https://github.com/zen-browser/desktop) on iOS
and Android. It signs in with your Firefox account, shows the tabs open on your
desktop, and shows your Zen **Spaces**, **Essentials**, pinned tabs and folders, laid
out like Arc Search.

> Status: **milestone 0**, proving the stack. The shared Rust core and its Swift
> bindings are built and tested; the app is a first Skip Fuse cut. See
> [docs/ROADMAP.md](docs/ROADMAP.md).

## How it fits together

- **Rust core** (`core/`): Mozilla's
  [application-services](https://github.com/mozilla/application-services)
  (Firefox Accounts, Sync, tabs), plus `zen-spaces`, a read-only client for the
  `spaces` collection Zen desktop syncs. One library, `libzen_core`, per platform.
- **Swift bindings** (`core/swift/ZenCore`): generated by UniFFI, the same Swift
  on iOS and Android.
- **App** (`app/`): one SwiftUI codebase, built for iOS natively and for Android with
  [Skip Fuse](https://skip.dev). WebKit on iOS, GeckoView on Android.

Details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · UI: [docs/UX.md](docs/UX.md) ·
Decisions: [docs/decisions](docs/decisions).

## Desktop setup

Open tabs sync with any Zen or Firefox. For **Spaces**, Zen desktop must have its
Spaces sync engine on: it's on in Zen Twilight; on release builds set
`services.sync.engine.spaces` to `true` in `about:config`. To sync unpinned tabs too,
set `zen.spaces-sync.normal-tabs` to `true`.

## Building

Everything builds on a Mac with Xcode, Rust and [Skip](https://skip.dev) (`brew install skiptools/skip/skip`).

| What | Command |
|---|---|
| NSS (once per platform) | `scripts/build-nss.sh desktop`, `ios`, `android` (needs `gyp-next` and `ninja`) |
| Rust tests | `. scripts/env.sh && (cd core && cargo test --workspace)` |
| Swift bindings + tests | `scripts/test-swift.sh` |
| Core for iOS | `scripts/build-core-apple.sh` |
| Core for Android | `scripts/build-core-android.sh` (needs `ANDROID_NDK_HOME`) |
| App | `scripts/generate-swift-bindings.sh`, then open `app/Project.xcworkspace` |

CI (`.github/workflows/ci.yml`) runs all of it on `macos-latest`, arm64 only: the Rust and
Swift tests, the iOS app and its end-to-end test on a simulator, and the Android APK. The
Android end-to-end test installs that same APK, unmodified, on arm64 Android running in
[Redroid](https://github.com/remote-android/redroid-doc) (Android as a container) on an
`ubuntu-24.04-arm` runner. GitHub's runners can't run the Android emulator, but Redroid
shares the host kernel, so arm64 apps run natively.

### End-to-end tests

Both platforms run the same native UI test: launch the app, open the address bar, load
`https://example.com`, check the page's title reaches the tab switcher, then open the
Space sheet. A screenshot is taken at each step.

- Android: `app/Android/app/src/androidTest/.../BrowsingTest.kt` (UiAutomator), run with
  `scripts/ci/start-redroid.sh` and `scripts/ci/run-android-e2e.sh`.
- iOS: `app/Darwin/UITests/BrowsingUITests.swift` (XCUITest), run with
  `xcodebuild test -scheme "ZenMobile App"`.

The screenshots appear inline in each CI run's summary (published to the
`ci-screenshots` branch by `scripts/ci/publish-screenshots.sh`).

## Caveats

- Sign-in uses Firefox for Android's public OAuth client id, since Mozilla doesn't
  register third-party Sync clients ([decision 0003](docs/decisions/0003-firefox-oauth-client.md)).
  Fine for personal use; talk to Mozilla before shipping anything.
- The app never writes to Zen's `spaces` collection yet. Desktop applies whatever it
  receives, so writes wait for a proper test harness.
